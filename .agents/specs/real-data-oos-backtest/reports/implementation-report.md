## Findings during implementation

- **No-lookahead test was initially mis-modeled.** The first
  future-revision test added a future *event_date*, which legitimately extended
  the auto-derived backtest window and changed output. Corrected to model the
  real PIT scenario — an in-window `event_date` whose `available_date` is after
  the window — which the provider correctly excludes. This is the genuine
  REQ-RDO-002 guard.
- **Real data is sufficient, not thin.** The initial assumption (real disk data
  too thin → `insufficient_data`) was wrong: FRED price proxies (SP500 since
  1992, copper) give a 413-month span and 4 price assets, so the CLI runs a
  *computed* comparison on real data today. The test and NEXT_STEPS were
  corrected to the honest reality, with the co-temporal-coverage limitation
  documented (not hidden).
